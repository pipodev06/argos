## Frontend servido por el server y bug de compilación en Linux (2026-09-24)
- `ARGOS_WEB_DIR` (directorio del build de Vite): el server sirve `web/dist` en `http://localhost:8080` sin Vite. `os.Root` confina `..` y symlinks; `/assets/*` immutable, `index.html` no-cache; fallback del SPA para toda ruta salvo `/health`, `/api/`, `/dl/`, `/install.` (esas dan 404 JSON); CSP solo en HTML/estáticos: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'` (`'unsafe-inline'` solo en estilos porque Radix/`react-remove-scroll` inyecta `<style>`; scripts estrictos). Variable vacía = desactivado; ruta inválida = el server no arranca (a diferencia de `ARGOS_AGENT_DIST_DIR`, que degrada). Con la SPA activa un POST a una ruta desconocida da 405 en lugar de 404. Verificado en Chrome sin errores de CSP.
- BUG (hallado por el CI de GitHub): `store/maintenance_windows.go` terminaba en `_windows.go` y Go lo trataba como archivo SOLO Windows: el server no compilaba en Linux/macOS. Renombrado a `maintenance_store.go`. Prevención: `scripts/check-go.sh` ahora hace `vet` cruzado con `GOOS=linux` y `GOOS=darwin` (incluye tests). Regla: ningún nombre de archivo Go debe terminar en un sufijo de SO/arquitectura salvo que sea intencional (solo `agent/internal/{checks,collector,service}`).
- CI (run `36069992196`): `web` y `go (agent)` pasaron (incluye `-race`); `go (server)` falló en `go vet` por el bug anterior. Pendiente confirmar `lint`, `govulncheck` y `go test -race` del server en Linux tras el fix.
