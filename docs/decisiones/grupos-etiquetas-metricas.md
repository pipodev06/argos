# Grupos, etiquetas, metricas nuevas y resumen (backend, 2026-09-24)
SQL de `data-infra-engineer` (00007-00011) copiado tal cual, probado con goose real (BD nueva, `argos_test`, copia con datos de `argos` en scratch ya borrada: Up -> Down a 6 -> Up). Sin dependencias nuevas. Decisiones del usuario: un grupo por host, `always_on`, grupo con hosts no se borra, max 200 grupos, 20 etiquetas por host.

- **Migraciones propias del backend** (no diseno de data-infra; revision pendiente, ver indice): `00012_host_status_offline` (CHECK `hosts_status_check` con `offline`; Down convierte offline en down) y `00013_enroll_token_group` (`enroll_tokens.group_id`, FK `ON DELETE SET NULL`: un token pendiente no bloquea borrar el grupo; el host enrolado queda sin grupo). 00007 sin cambios salvo el comentario de la nota. 00010 = diseno (legacy hasta hoy + 7 diarias desde hoy): `disk_samples` necesita crear `hoy+7` en el primer ciclo del mantenimiento.
- **Errores**: `409 group_exists`, `409 group_not_empty` (FK RESTRICT: Postgres responde 23001, no 23503; `isFKViolation` acepta ambos), `409 too_many_groups` (lock advisory + count), `422 too_many_labels` (chequeo previo + trigger de BD), `422 group_not_found` (grupo en el body inexistente), `422 unknown_hosts` (bulk con id inexistente; todo o nada). Id en la URL inexistente = 404.
- **Rutas**: `GET/POST /groups`, `PATCH/DELETE /groups/{id}`, `PUT /hosts/{id}/group|labels`, `GET /labels`, `POST /hosts/bulk`, `GET /summary`; `enroll-token` acepta `group_id`.
- **Formas finales**: `POST/PATCH /groups` -> `{group:{id,name,down_after_seconds,always_on,host_count}}`, `DELETE` -> `{}`; `PUT /hosts/{id}/group` -> `{group:{id,name}|null, status}` (el estado puede cambiar por reclasificacion); `PUT /hosts/{id}/labels` -> `{labels:[{key,value}]}` (por clave); `POST /hosts/bulk` -> `{affected:n}` (hosts que cambiaron de verdad; `set_group` con `group_id:null` = sin grupo, la clave es obligatoria; `remove_label` con `value` solo quita esa pareja; `disable` = revocar; se rechazan campos que no aplican). `summary.by_group` solo incluye grupos con hosts, mas `{group_id:null,name:"Sin grupo"}` al final si hay (el front puede ignorar el rotulo y usar `group_id: null`); `top_*.mount` solo en `top_disk`.
- **Validacion**: clave de etiqueta `^[a-z][a-z0-9_.-]{0,62}$`; valor 1-128 sin control (se recorta); nombre de grupo 1-64 recortado.
- **Detalle de host**: `host` suma `group` y `labels`; `info` (siempre objeto, campos null si el agente no lo manda, `ips` `[]`, `mem_total_mb` de `host_latest`); `latest` suma `swap_used_mb, swap_total_mb, load1, load5, load15, battery_pct, battery_charging`; `disks:[{mount,used_mb,total_mb,ts}]` = ultima muestra por montaje en los ultimos 7 dias (un equipo apagado mas tiempo no muestra discos).
- **Series**: cada punto suma `swap_used_mb, swap_total_mb, load1, load5, load15, battery_pct` (null sin dato; rango largo pondera por `samples` y solo cuenta horas con dato). Rollup por hora: swap avg/max/total, load1 avg/max, load5 y load15 avg, bateria avg/min (`rollup.sql`).
- **Retencion de disco**: `disk_samples` particionada por dia UTC, `ARGOS_DISK_RETENTION_DAYS` (30, minimo 8), sin marca de agua ni resumen; en `partitionedTables` y `dropExpired`.
- **Auditoria**: `group_created|updated|deleted`, `host_group_set`, `host_labels_set` (solo cantidad), `hosts_bulk` (`action`, `count`, `group_id`, `key`; nunca valores de etiquetas). Lista blanca ampliada con `action, group_id, name, always_on, down_after_seconds, key`.
