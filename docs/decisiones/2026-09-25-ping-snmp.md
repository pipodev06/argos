# Punto 8: dispositivos sin agente (ping ICMP + SNMP) - diseño

Base leída: decisión chequeos-servicios (solo agente ejecuta; `ARGOS_CHECK_ALLOW` local que el server no amplía; secretos con `secretbox`), `notify/policy.go` (bloquea rangos privados por defecto: es la lógica inversa a la que necesitamos), `agent/internal/checks/policy.go` (allowlist host/IP/CIDR[:puerto], decidida al arrancar), migraciones 00001/00007 (`hosts.agent_token_hash NOT NULL`, `group_id`, `host_groups.always_on`). No verifiqué gosnmp en línea (ver 3).

## 1. Dónde corre la sonda

Modelo de amenazas: una sonda que hace ICMP/UDP161 a IPs elegidas por un admin es un escáner interno (SSRF/reconocimiento) y un amplificador si el server se compromete. Actores: admin malicioso/cuenta admin robada (elige destinos), atacante con el server (ordena sondear todo).

- (a) Server: simple, un solo lugar, pero el server suele estar en DMZ/nube y no ve las LAN; y un server comprometido escanea todo su segmento. Además rompe la decisión vigente (sondas del server = fase 2, sin ampliar por API).
- (b) Agente como "colector" de una red: ve la LAN real, reutiliza el canal ya autenticado (`checks_rev`, reporte), y la allowlist queda LOCAL en el agente, igual que `ARGOS_CHECK_ALLOW`: el server no puede ordenar sondear fuera de lo que el dueño del equipo autorizó. Consistente con lo decidido.
- (c) Ambos: doble superficie y doble código; no ahora.

**Recomendación: (b)** y dejar (a) fuera (fase 2 sigue pendiente, con su propia decisión).

Autorización: nuevo `ARGOS_PROBE_ALLOW` en el agente (CIDRs/IPs, puertos fijos 161 y ICMP), vacío por defecto = colector desactivado. Rechazo por defecto de loopback, link-local, metadata (169.254/16), multicast, broadcast; máscara mínima /24 por entrada y tope de N objetivos por colector (ej. 256). Resolver DNS una vez y validar la IP resuelta (anti-rebinding). El server solo asigna dispositivos a un colector; el agente descarta lo que caiga fuera de su allowlist y reporta `blocked`. Sin descubrimiento automático de subredes en MVP (alta manual o CSV; el escaneo es justo el riesgo).

Privilegios ICMP sin root, por orden: (1) socket UDP-ICMP `icmp.ListenPacket("udp4",...)` de `x/net/icmp`: Linux requiere `net.ipv4.ping_group_range` que incluya el GID del servicio (documentar sysctl; el instalador NO lo toca); macOS lo permite sin root. (2) Windows: `IcmpSendEcho` de `iphlpapi.dll` (sin privilegios, ya se usa syscall en `service_windows.go`). (3) Fallback: ejecutar `ping` del SO con argv fijo (`ping -c 1 -W 2 -- <ip>` / `ping -n 1 -w 2000 <ip>`), IP ya validada como `netip.Addr` (nunca hostname libre), salida no interpretada salvo RTT por regex acotada, `exec` sin shell. Rechazado: CAP_NET_RAW (agente hoy sin capacidades; ampliaría el blast radius). Si ninguna opción sirve, el chequeo ping da `unknown/unsupported`.

## 2. Modelo de datos

Opciones: (A) `hosts.kind IN ('agent','device')` con `agent_token_hash` nullable; (B) tabla nueva `devices`.
Recomiendo **A**: estados up/down/offline, `group_id`, labels, `store.Scope`, alertas, mantenimiento y las pantallas de `/hosts` ya operan sobre `hosts`; con B habría que duplicar Scope y cada consulta. Costo: revisar cada uso de `agent_token_hash` (autenticación de reporte debe exigir `kind='agent'`; test explícito: un device nunca autentica) y constraint `CHECK ((kind='agent') = (agent_token_hash IS NOT NULL))`.

Migración 00018 (esbozo):
- `hosts`: `kind TEXT NOT NULL DEFAULT 'agent'`, `address INET NULL` (solo device), `collector_host_id UUID NULL REFERENCES hosts(id)` (ON DELETE RESTRICT), `snmp_profile_id`.
- `snmp_profiles(id, name, version, security_level, username, auth_proto, priv_proto, secret_enc BYTEA, ...)`: secreto cifrado igual que `service_check_defs`; reutilizable por N dispositivos; la API nunca lo devuelve.
- `device_probe_state`/`ping` y SNMP se guardan como chequeos: reutilizar `service_check_defs` con nuevos tipos `ping` y `snmp` ligados al host device (cero tablas de eventos nuevas: `service_check_state/events`, alertas `kind='service_check'` ya cubren umbrales). Métricas de interfaz: tabla `device_if_metrics(host_id, if_index, ts, oper, in_octets, out_octets)` solo para interfaces marcadas `monitored` (tope 8 por defecto, 64 máximo).
- Estado del device: `up` si ping o SNMP responde; el "último visto" lo actualiza el colector; si el colector mismo está down/offline, sus devices pasan a `unknown` (no `down`: evita tormenta de falsas alertas). Grupo `always_on` decide down vs offline igual que hoy.
- Scope: hereda por `group_id`; permisos para gestionar colector/allowlist/perfiles: solo admin. Un viewer con alcance ve el device y no ve address/perfil si no es admin (decisión pendiente, ver preguntas).

## 3. SNMP

Versiones: v3 con authPriv obligatorio por defecto (SHA-256/512 + AES-128/256; rechazar MD5/DES). v2c solo si un admin lo habilita explícitamente en el perfil (`allow_v2c` con confirmación y aviso en UI), solo lectura, y siempre limitado: solo GET/GETBULK a OIDs de la lista blanca, sin walk libre. v1 no. Community tratada como contraseña (cifrada, nunca en logs ni API; el log de auditoría no la incluye).

OIDs mínimos (lista fija en código; el admin no escribe OIDs libres en MVP): sysUpTime `1.3.6.1.2.1.1.3.0`, sysName/sysDescr `1.1.5/1.1.1.0`, ifOperStatus `2.2.1.8`, ifHCInOctets/ifHCOutOctets `31.1.1.1.6/10` (fallback ifInOctets `2.2.1.10/16` si no hay HC), ifDescr/ifName para etiquetar, hrProcessorLoad `1.3.6.1.2.1.25.3.3.1.2`, hrStorage (disco/RAM) opcional, prtMarkerSuppliesLevel para impresoras (fase posterior).

Librería: `github.com/gosnmp/gosnmp` (BSD-2, mantenida, v1/v2c/v3 con SHA-2 y AES, GETBULK/BulkWalk, timeouts y reintentos configurables) vs implementar lo mínimo. Implementar a mano BER + USM v3 (localización de claves, autenticación HMAC, cifrado AES-CFB, descubrimiento de engine/ventanas de tiempo) es ~1500 líneas de criptografía a medida con alto riesgo de errores; el parser BER frente a datos hostiles es superficie de ataque (fuzzing requerido en ambos casos). **Recomiendo gosnmp**, fijada por versión, con `govulncheck` en CI y wrapper propio de ~200 líneas que impone los límites. Antes de aprobar, verificar en pkg.go.dev: versión vigente, soporte SHA-256/512+AES-256 y CVE abiertos (no lo hice aquí). Es dependencia nueva del agente: requiere tu aprobación.

Límites (en el wrapper, no configurables por API por encima del tope): timeout 3 s, 1 reintento; concurrencia colector ≤16 dispositivos simultáneos y 1 solicitud en vuelo por dispositivo; max-repetitions 10; walk solo de las columnas de la lista blanca, ≤256 varbinds por dispositivo por ciclo y ≤1 MiB por ciclo; respuesta >64 KiB se descarta; solo lectura (jamás SET). Circuit breaker: 3 ciclos fallidos ⇒ backoff exponencial hasta 5 min (evita martillar un equipo caído o bloquear cuentas USM).

## 4. Frecuencia y volumen (estimado por cálculo, no medido)

Propuesta: ping cada 60 s (3 paquetes de 64 B, ~1 s); SNMP cada 60 s para uptime/estado y cada 5 min para contadores de interfaz/CPU. Piso de intervalo: 30 s ping, 60 s SNMP.

| | 100 dispositivos | 1000 dispositivos |
|---|---|---|
| Ping (~200 B/ciclo) | 1.7 pkt/s, ~0.3 KB/s | 17 pkt/s, ~3 KB/s |
| SNMP: switch 48 puertos ≈ 3 columnas x 48 = 144 varbinds ≈ 3 GETBULK (~0.5 KB c/u) por 5 min; escalares ~1 req/min | ~1.5 req/s, ~2 KB/s | ~15 req/s, ~20 KB/s |
| Concurrencia necesaria (1 s por dispositivo, 16 en vuelo) | 1 colector sobra | 1000/60 s ≈ 17 en vuelo: 1-2 colectores por red; recomendable repartir |
| Filas de series (60 s estado + 5 min contadores, 8 if/dispositivo) | ~0.15M + 0.23M filas/día | ~1.4M (mejor guardar solo cambios de estado + muestra RTT a 5 min = 0.29M) + 2.3M filas/día (~100 MB/día crudo con 40 B/fila) |

Conclusión: red y CPU son triviales; lo que escala mal es el almacenamiento de interfaces. Mitigación: solo interfaces marcadas, retención con submuestreo (mismas reglas de retención ya existentes), y el ciclo de reporte hacia el server agrupado en el reporte normal (el server ya acepta lote con tope ~15 KiB; para 1000 dispositivos ese tope hay que subirlo o paginar por colector; verificar en tanda 1).

## 5. Tandas

1. **Ping + modelo**: migración 00018 (`kind`, `address`, `collector_host_id`, CHECK), API de dispositivos (admin CRUD, Scope en lectura), tipos de chequeo `ping`, `ARGOS_PROBE_ALLOW` + validación (anti-rebinding, prefijos bloqueados) en el agente, ICMP por los 3 caminos, estado `unknown` si el colector cae. Tests: política (tabla: loopback/metadata/IPv4-mapped/CIDR fuera), argv del ping sin inyección (hostname con `;`/espacios rechazado), device nunca autentica reporte, Scope (viewer de otro grupo no lo ve), constraint BD, colector caído ⇒ unknown, `-race`.
2. **SNMP v3**: `snmp_profiles` cifrado, wrapper gosnmp con límites, OIDs fijos, ifTable acotado, v2c bajo bandera. Tests: contra un simulador (gosnmp tiene ejemplos; o snmpsim en contenedor), respuesta gigante/varbinds excesivos cortados, timeout/backoff, MD5/DES rechazados, secreto ausente en API/auditoría/logs, `fuzz` del decodificador del wrapper, `govulncheck`.
3. **Pantallas y alertas**: alta de dispositivo/perfil, asignar colector, vista de interfaces, reglas `service_check` para umbrales (ifOperStatus, CPU), tile/lista mezclando kinds, retención y submuestreo. Tests: unitarios de formulario, e2e alta→up→down→alerta.

## Tanda 1 hecha (2026-09-25): ping + modelo de dispositivos (server 00023 + agente colector)
- Contrato entre server y agente (congelado): el chequeo `ping` de un DEVICE llega en `checks.items` del COLECTOR (`{id, type:"ping", name, interval_s, timeout_ms, retries, warn_ms, crit_ms, target:"<IP literal>", device_id}`); un ping con alcance de grupo genera un item por dispositivo con `id` = UUID v5 determinista `store.PingItemID(check, device)`; el agente reporta `check_id` = ese `id` en `services[]` y el server guarda estado/eventos/alertas sobre el device. Tope de entrega 50 items / 15 KiB sin cambios.
- Servidor: migración 00023 (`hosts.kind agent|device`, `address INET`, `collector_host_id` RESTRICT, CHECKs de coherencia, tipo `ping` y alcance `device` en `service_check_defs`); reporte de agente solo con `kind='agent'`; API `/api/v1/devices` (GET lista `{items,next_cursor,total}` y detalle con Scope y 404 idéntico; POST/PATCH/DELETE solo admin; `address` y `collector` solo para admin). DTO: `{id, name, kind:"device", address*, collector*:{id,name}, group, status, status_changed_at, last_seen_at, evaluated, created_at}`. Errores: 400 `invalid_body`, 409 `device_exists`/`too_many_devices` (máx 1000), 422 `collector_invalid`/`group_not_found`/`device_not_found`. Chequeo ping: `POST /service-checks {type:"ping", warn_ms, crit_ms, scope:{type:"all"|"group"|"device", ...}}` (sin `target_host`; `scope device` solo para ping). `/hosts` y el detalle traen `kind`; `/hosts` no muestra `address`.
- Estado del device: un ping que responde lo pone `up`; sin respuesta, `down`/`offline` según `always_on` del grupo; un resultado `unknown` no cuenta; si el colector no está `up`, sus devices pasan a `offline` (no hay estado `unknown` nuevo; el DTO trae `evaluated:false`).
- Agente colector (`agent/internal/checks/ping*.go`): `ARGOS_PROBE_ALLOW` (vacío = desactivado; IPs/CIDRs, /24 mínimo (/120 IPv6), bloquea loopback/link-local/multicast/broadcast/no especificada/IPv4-mapped en esos rangos), `ARGOS_PROBE_MAX_TARGETS` (256) y `ARGOS_PROBE_MAX_CHECKS` (20 por defecto, máx 1000; añadidas por el agente, aprobadas por defecto). ICMP nativo sin root (socket UDP-ICMP con `x/sys/unix` en Linux/macOS; `IcmpSendEcho` en Windows) y respaldo `ping` del SO con argv fijo y ruta absoluta; IPv6 solo por `ping` del SO; semáforo de 16. Linux exige `net.ipv4.ping_group_range` con el GID del servicio (el instalador no lo toca).
- Deuda: sin ICMPv6 nativo; RTT del `ping.exe` con locale raro depende de un regex; socket ICMP y `ping` reales de Linux/macOS sin ejecutar (solo vet cruzado); sin re-habilitar dispositivos deshabilitados; sin tope de entrega propio para colectores con >50 items; `address` no sale en `/hosts`; el detector deja un `unknown` fresco sin evaluar. Costó 257 k tokens el agente del servidor (95 llamadas): la tanda fue grande; partir en dos la próxima vez.
- Pendiente: tanda 2 (SNMP v3, `gosnmp`) y tanda 3 (pantallas: alta de dispositivos/perfiles, colectores, alertas).

## Tanda 2 hecha (2026-09-25): SNMP v3 MVP (server 00024 + agente colector con gosnmp v1.45.0)
- Alcance: perfiles SNMP + chequeo `snmp` con 2 métricas fijas: `reachable` (GET sysUpTime; `value` = uptime en s) e `if_oper` (GET ifOperStatus.<if_index>; 1=up, 2=down, otro=warn). Sin OIDs libres, walk, contadores ni SET. `if_oper` no alimenta el estado del device; un device sin perfil no recibe chequeos snmp.
- Entrega al colector (`checks.items`): `{id, type:"snmp", ..., target, device_id, metric, if_index?, snmp:{version:3,user,level:"authPriv",auth_proto:SHA256|SHA512,auth_pass,priv_proto:AES128|AES256,priv_pass}}` o `snmp:{version:2,community}` si el perfil es v2c permitido; secretos descifrados SOLO en la entrega (canal TLS+bearer). Resultados como el ping; `detail` nuevos `auth_failed` y `no_such_object` (ambos con status `unknown`; timeout → `down`).
- Agente (`agent/internal/checks/snmp*.go`): solo GET, puerto 161 fijo, timeout 3 s + 1 reintento del wrapper, ≤16 dispositivos en vuelo con 1 solicitud cada uno, circuit breaker (3 fallos → backoff 30 s hasta 5 min), misma allowlist `ARGOS_PROBE_ALLOW` del ping (vacía o fuera → `blocked`), rechaza MD5/SHA-1/DES, authNoPriv, v1 e `if_index` fuera de 1–65535 antes de enviar; v3 nunca degrada a v2c; AES256 = Blumenthal (`gosnmp.AES256`, no `AES256C` Cisco); secretos fuera de logs, `%v` y resultados.
- Servidor: migración 00024 (`snmp_profiles` con secretos cifrados AES-256-GCM/`ARGOS_SECRET_KEY`, `hosts.snmp_profile_id` FK RESTRICT, tipo `snmp` en `service_check_defs`). API admin `/api/v1/snmp-profiles` (GET `{items}`, GET `/{id}` `{profile}`, POST 201, PATCH, DELETE). Perfil: `{id,name,version:3|2,allow_v2c,username|null,level:"authPriv"|null,auth_proto,priv_proto,has_secret,has_community,device_count,created_at,updated_at}`. POST v3: `{name,version:3,username,auth_proto,auth_pass,priv_proto,priv_pass}` (pass 8–128); POST v2c: `{name,version:2,allow_v2c:true,community}`; PATCH: name, username, auth/priv proto y pass, community (versión inmutable, sin null). Errores: 400 invalid_body; 409 profile_exists, too_many_profiles (100), profile_in_use; 422 profile_not_found; 503 secret_key_missing. `PATCH /devices/{id}` acepta `snmp_profile_id` (uuid|null); el DTO de device (solo admin) trae `snmp_profile:{id,name,version}`. `POST /service-checks {type:"snmp", metric, if_index?}` (scope all|group|device; sin warn/crit ni target).
- Deuda: sin simulador SNMP v3 authPriv (v3 solo contra un agente mudo y el mapeo de errores; v2c sí contra simulador UDP) → falta probar con un equipo real v3; sin fuzz; sin `-race` local; `CheckSecretKey` de arranque solo valida claves de canales (no perfiles ni chequeos http); el tope de 50 items/15 KiB de entrega al colector se comparte con el ping. Costó: agente 97 k tokens, servidor 193 k.
- Pendiente: pantallas de perfiles SNMP y chequeo `snmp` (tanda 3b); contadores de interfaz, CPU y almacenamiento; probar con un equipo real.
